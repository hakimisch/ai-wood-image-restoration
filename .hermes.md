## Strict Rules

### 1. No Fabricated Metrics
NEVER invent PSNR, SSIM, or LPIPS metrics. Every numerical claim must trace to:
   - `eval_results/` CSV files (preferred — standardized CenterCrop, LPIPS included)
   - SQLite `model_metrics` table (historical context only — different methodology)

### 2. Three Incompatible Evaluation Systems
These systems CANNOT be compared directly — note the methodology in any cross-reference:

| System | Scope | Test Set | Weights Saved? | Status |
|--------|-------|----------|----------------|--------|
| **Old DB** | IDs 1-24 | Unknown order, ~50 images | No (.pth_filename=NULL) | Historical only |
| **Compound DB** | IDs 33-56 | Sequential DB ID order | Yes | Reproducible with caveats |
| **Standardized CSV** | evaluate.py --all | Fixed 50 images, CenterCrop, LPIPS | Root weights | **GROUND TRUTH** |

Test sets have **zero overlap** across systems. Always treat CSV as ground truth; label DB values as "historical context" in any writing.

### 3. Weight File Provenance
- **Root `weights/`** = final 50-epoch acceptable quality weights.
- **`weights/old/`** = duplicates of root weights, early-epoch runs, orphaned Gaussian-only candidates.
- Gaussian-only training runs (DB IDs 2, 4) have `pth_filename=NULL` — **unreproducible**.
- **Constraint: No new 50-epoch model training** for thesis finalization.

### 4. Windows/WSL Workflow
- Windows Python venv is at `app/torch_env/` (not root `torch_env/`)
- Must use `-X utf8` flag when running Windows Python from WSL to avoid UnicodeEncodeError on emoji in print statements
- WSL paths: `/mnt/c/Hakimi/Internship/GUI Image Restoration/`
- All evaluation scripts run via `python -X utf8` from the venv

### 5. Workflow Order
**Phase 1 (run scripts) → Phase 2 (edit text) — never reverse this order.**
Always validate data before writing claims. Run evaluate.py, generate visual evidence (FFT, bar charts), then cross-reference with the draft.
